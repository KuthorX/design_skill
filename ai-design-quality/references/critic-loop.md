# 评审子代理循环

## 流程

```
loop:
  1. 实现代理 → 截图当前设计（固定视口、固定 DPR）
  2. 在全新上下文中调用评审子代理，只传截图 + 固定评审提示
  3. 评审返回：目标美学 / 顶级工作室做法 / 最大差距 / 10 分制评分
  4. 若评分 ≥ 阈值（默认 9，不告诉评审）→ 结束
  5. 否则把评审反馈交给实现代理修改，回到 1
停止保险：
  - 前 2 轮分数未上升 → 停下来人工介入，检查评审标准是否可达
  - 轮数上限（建议 6）
```

模型分配：评审用最强模型；实现用小而强的模型。

## 评审提示词（每轮完全相同）

```
你是一位世界级的设计总监。你只会看到一张截图，没有任何背景信息。

1. 判断这个设计试图达成的目标美学是什么。
2. 想象一家顶级设计工作室会如何执行这个美学。
3. 列出当前作品与之最大的 3–5 个差距。兼顾整体构图（层级、节奏、留白）与细节（字距、对齐、材质、边缘）。
4. 严厉惩罚：过度堆砌、装饰性渐变与光晕、通用模板骨架、任何明显 AI 生成的模式。
5. 给出紧凑、具体、大胆、有主见的修改建议，每条一句话。
6. 最后给出 10 分制评分，只给整数，并用一句话说明为何不是满分。

不要客气，不要平衡措辞。
```

## 更客观的变体：五图排名

```
附件有 5 张截图，其中 4 张来自专业工作室，1 张是待评作品。
按整体精致度从高到低排名，说明每张的名次理由。
然后单独对待评作品给出 3–5 条追平前三名所需的具体修改。
```

参考图只作为基线与情绪板，评审不得要求待评作品复制它们。

## 常见失败

- 评审看到了代码或上轮评语 → 分数被污染，必须全新上下文。
- 告诉评审"打到 9 分就结束" → 评审会放水。
- 标准是"美不美"或"像不像 AI" → 主观漂移，改成对比工作室或排名。
- 没先验证收敛 → 代理在无法达标的标准上循环烧 token。
