# 提示词模板

## 种子提示（探索阶段）

```
先运行下面的命令生成一个随机字符串：
LC_ALL=C tr -dc 'A-Za-z0-9' </dev/urandom | head -c 256; echo

把这个字符串当作唯一的创意灵感来源。从它的规律中推导出本次设计的：
- 主色与辅色（可把字符映射为色相、明度、饱和度）
- 版式骨架（对称/不对称、网格密度、留白策略）
- 字体气质（衬线/无衬线/展示体，粗细与字距）
- 材质与隐喻（纸、金属、玻璃、像素、手绘……）

然后用专业判断把这个方向执行到最好。
字符串只是灵感，不得在成品中出现，也不要在设计中暗示它的存在。
先用三句话说明你推导出的方向，再开始实现。
```

## 求广提示（三步法第 1 步）

```
为 <产品> 的 <页面/资源> 给我 20 个高层视觉方向。
每个只写一行：一个鲜明的隐喻 + 一个关键视觉手法。
刻意保持浅层，不要展开，不要考虑可行性。
至少 5 个要听起来"不靠谱"。
```

## 打磨提示（三步法第 2 步）

```
我看了方向 3、7、12 的草图，反应如下：
- 3：隐喻好，但配色俗，像电商促销
- 7：缺质感，需要纸张或颗粒
- 12：太满，留白不够
按我的反应把这三个方向各打磨成一段 100 字内的视觉定义。
```

## 构建提示（三步法第 3 步）

```
把方向 7 写成一份交给执行代理的构建提示：
- 不超过 200 字
- 包含目标美学、配色、版式、字体、材质、禁止事项
- 不包含任何代码细节
```

## 删减提示（交付阶段）

```
对当前设计做一轮纯删减：
删掉所有不承担信息或交互功能的元素（装饰光晕、多余容器、冗余标签、随机强调色、比原生更差的自定义控件）。
不允许新增任何东西。
完成后列出删除清单和保留理由。
```
